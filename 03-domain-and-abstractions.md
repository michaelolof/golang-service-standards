# 03 · Domain modelling and abstractions

This covers how business concepts become Go types, and when to introduce an interface, service, adapter or generic.

It builds on the layer table in [01-project-layout.md](01-project-layout.md#lay-6--one-internal-taxonomy).

## The test every abstraction must pass

A type, interface, package or layer must earn its place by doing at least one of these:

1. **Hide a dependency**, such as an SDK, the clock or the network.
2. **Enforce an invariant**, so the value cannot exist in an invalid state.
3. **Have two or more real implementations or consumers today.** Test doubles count as implementations. Hypothetical future ones don't.

If it does none of these, inline it. Most of the smells listed at the end of this document fail this test.

## Rules at a glance

| ID | Rule | Enforced by |
|---|---|---|
| DOM-1 | Every aggregate identity is a named `[16]byte` type in `domain`, generated by an injected `ids.Generator`. It keeps that type in every layer. | depguard, review |
| DOM-2 | Money is one value type with unexported fields and a validating constructor. | review |
| DOM-3 | `domain` and `core` never call `time.Now()`. They take `now` or a `clock.Clock`. Times are UTC. | forbidigo |
| DOM-4 | Domain types are used across every boundary. They may carry tags and standard-library driver methods; `domain` imports no driver. | depguard |
| DOM-5 | Value objects come from `New…`/`Parse…` returning an error. Entities have `Validate() error`. | review |
| DOM-6 | Closed sets are enumx types declared one way, with `Parse`, `Validate` and a sorted `Oneof`. | arch test, reassign |
| DOM-7 | One enum and one transition table per state machine. State changes only via `TransitionTo`. | test over `Values()` |
| ABS-1 | One interface per dependency per consuming package, declared there, typed only with domain and stdlib types. No interface without a consumer and an implementation. gofi's `Deps` is the one interface with no method limit. | interfacebloat, iface, arch test |
| ABS-2 | Implementations assert the interface they satisfy and return concrete types. Only gofi's `Deps` accessors and functions returning gofi's own interfaces return an interface. | arch test, ireturn |
| ABS-3 | Name by role: `-er`, `Store`, domain nouns. Never `I*`, `*Iface`, `*Impl`, `*Adapter` or `*Manager`. | arch test |
| ABS-4 | Pure rules are free functions. Orchestration lives in one `Service` per capability. | review |
| ABS-5 | `New(Deps) (*Service, error)`, validated. No `With*` mutators, exported mutable fields or silent no-op defaults. | arch test |
| ABS-6 | One method and one file per use case: `(ctx, XArgs) (XResult, error)`. | review |
| ABS-7 | One adapter package per external system, with one file per role. It wraps the SDK once, leaks no SDK types, and translates errors. | depguard, analyzer, review |
| ABS-8 | Generics only for logic that doesn't depend on `T`. Never type-switch on `T`. | analyzer, review |
| ABS-9 | No functional options in services or adapters. No embedded concrete types. Registries are immutable and keyed by enums. | embeddedstructfieldcheck, review |

## Domain types

### DOM-1 · Typed IDs keep their 16-byte form

**Rule.**
- **One type per identity.** Each aggregate's identity is a named type in `domain` over `[16]byte`: `type TransferID [16]byte`. A ULID and a UUID are both 16 bytes. That is their original type, and it stays that type through every layer: HTTP, core, repository, jobs, events.
- **Text only where text is needed.** The text form (`01JBX9K3Z8T6V2M4N7P5Q1R0S9`) exists in JSON, URLs and logs, produced by the type's own methods. Nothing converts an ID to `string` to pass it around.
- **The method set.** Every ID type has the same small set of methods, in the file that declares it:
  - `Parse<Type>(s string) (<Type>, error)`, the one way in from untrusted text. It returns `ErrKindInvalidInput`.
  - `String`, `MarshalText` and `UnmarshalText`, which cover `encoding/json`, slog and `fmt`.
  - The methods the repo's store needs, from the table below, and nothing else.
- **New IDs** come from an injected `ids.Generator` that returns `[16]byte`, never from a driver call in core. The generator produces the kind of ID the store expects:
  - a time-based UUID for Scylla `timeuuid` columns;
  - a ULID elsewhere.
- **No driver ID types** (`gocql.UUID`, `bson.ObjectID`, `pgtype.UUID`) anywhere, including repository signatures.

**What each boundary needs.** Every row was tested, on gofi v0.10.4, pgx v5.9.2, gocql v1.7.0 and mongo-driver v2.8.0.

| Boundary | What the ID type needs | Result without it |
|---|---|---|
| `encoding/json`, slog | `MarshalText`/`UnmarshalText` → `"01JBX9K3Z8T6V2M4N7P5Q1R0S9"` | an array of 16 numbers |
| gofi path, query, body and response (v0.10.4) | one `CustomSpec` per ID type, and a `spec:"transfer-id"` tag on the field, on `TransferID` or `*TransferID`. A nil `*TransferID` in a response is `null`. OpenAPI documents the field as `type: string, format: ulid`. A malformed ID gets a 400: `ulid: bad data size … at request Path(transfer_id)` | base64 decoding, and `format: byte` in OpenAPI |
| pgx, `UUID` column (v5.9.2) | nothing. pgx encodes and scans a named `[16]byte` natively, in binary and text formats | |
| pgx, `STRING` column | don't. Writing works through `MarshalText`, but scanning fails (`cannot scan text (OID 25) … into *TransferID`). Store IDs in `UUID` columns | |
| gocql, `uuid`/`timeuuid` (v1.7.0) | a conversion at the call: `gocql.UUID(id)` to bind, `(*gocql.UUID)(&id)` to scan. Both are free, because the types share `[16]byte` | `can not marshal TransferID into uuid` |
| Mongo driver v2 (v2.8.0) | `MarshalBSONValue() (byte, []byte, error)` and `UnmarshalBSONValue(byte, []byte) error`, storing binary subtype 4. The signatures use `byte`, so `domain` imports nothing from the driver | binary subtype 0 |

gocql is the one driver whose own interface (`MarshalCQL(info gocql.TypeInfo)`) would make `domain` import the driver. The conversion at the call avoids that. Conversions are permitted only at actual external input/output or third-party vocabulary boundaries, with the reason clear at the conversion site.

**Why.**
- Typed IDs turn swapped arguments into compile errors.
- A 16-byte ID never pays for text conversion inside the service. Converting a UUID to text costs about 18 ns and a 48-byte allocation; parsing it back costs 35 ns (measured).
- The storage engine doesn't leak into the layers above it.

A driver type used as the ID type spreads everywhere:
- `gocql.UUID` appeared in more than 100 non-test files outside `repository/` and `adapters/`;
- HTTP schemas declared `ProjectID gocql.UUID`;
- IDs were created with `gocql.TimeUUID()` at 284 call sites and parsed with `gocql.ParseUUID` at 102.

So a core test can't create an ID without the Scylla driver, and the API contract is written in terms of a database type. The other mistake is to carry IDs as `string`: 618 `string` ID fields in one `domain` package, or a `type RecordID string`.

**Don't.** Three positional `string` IDs can be passed in any order without a compiler error:

```go
GetTransferForAdmin(ctx context.Context, orgID, tenantID, transferID string) (Transfer, error)
```

**Don't.** A database driver type used as a domain ID:

```go
type LifecycleRecord struct {
	ProjectID, EventID gocql.UUID
	// ...
	LeaseOwner gocql.UUID
```

**Canonical:**

```go
// internal/domain/transfer.go
// TransferID identifies a transfer. It is a ULID in its 16-byte form.
type TransferID [16]byte

func ParseTransferID(s string) (TransferID, error) {
	id, err := ulid.ParseStrict(s)
	if err != nil {
		return TransferID{}, errx.WrapKind(1793623712794, errkinds.ErrKindInvalidInput, err)
	}

	return TransferID(id), nil
}

func (id TransferID) String() string                { return ulid.ULID(id).String() }
func (id TransferID) MarshalText() ([]byte, error)  { return ulid.ULID(id).MarshalText() }
func (id *TransferID) UnmarshalText(b []byte) error { return (*ulid.ULID)(id).UnmarshalText(b) }

// internal/foundation/ids/ids.go
// Generator returns new unique 16-byte IDs.
type Generator interface{ New() [16]byte }

// internal/core/transfer/initiate.go
t := domain.Transfer{ID: domain.TransferID(s.ids.New()), CreatedAt: s.clock.Now()}

// internal/http/specs/ids.go: one line per ID type
var TransferID = idSpec[domain.TransferID]("transfer-id")

// idSpec defines the gofi spec for one ID type, through its text methods.
func idSpec[T encoding.TextMarshaler, PT interface {
	*T
	encoding.TextUnmarshaler
}](specID string) gofi.CustomSpec {
	return gofi.DefineCustomSpec(gofi.SpecDefinition{
		SpecID: specID,
		Type:   "string",
		Format: "ulid",
		Encode: func(val any) (string, error) {
			text, err := val.(T).MarshalText()

			return string(text), err
		},
		Decode: func(val any) (any, error) {
			var id T

			text, _ := val.(string)
			err := PT(&id).UnmarshalText([]byte(text))

			return id, err
		},
	})
}
```

`wire.go` registers every ID spec with `r.RegisterSpec(...)` before it registers routes. gofi panics at registration if a `spec` tag names an unregistered spec.

**Limits on gofi v0.10.4.** Watch for these three cases:

| Case | What happens | What to do |
|---|---|---|
| A list of IDs, `[]TransferID` | no spec per element, so it's base64 in requests and responses, not the ID's text | Use `[]struct{ ID TransferID }`, with the `spec` tag on `ID` |
| An ID field with no `spec` tag | base64 instead of the ID's text, with no error | Check in review that every ID field has the tag |
| An optional `*TransferID` in OpenAPI | a nil one is written as `null`, but the document doesn't mark it `nullable`, so a client generated from it says the field is never null | Clients handle `null` on optional IDs (parked: see [decisions.md](decisions.md)) |

If your project uses Scylla, its adapter's generator returns `[16]byte(gocql.TimeUUID())`, and the repository binds and scans with the conversions in the table. Tests pass `idstest.Sequence(...)` as the generator (TEST-12).

### DOM-2 · One money type

**Rule.**
- Money is always stored in its smallest unit, such as cents or wei, as an integer. `domain.Amount` holds that integer plus the asset, in unexported fields.
- Choose an integer type that fits your largest amount. `int64` fits most currencies. An 18-decimal token overflows it at about 9.2 tokens, so it needs `*big.Int`. `Amount` hides the choice from callers.
- It is built only through `NewAmount` or `ParseAmount`, which return `(Amount, error)`.
- No `float64` anywhere near money.
- No raw `int64` or `*big.Int` in ports.

**Why.** Without one type, money ends up in several representations, with lossy conversions between them:

- `AmountMinor int64` in entities.
- `new(big.Int).SetInt64(...)` in the service.
- `req.Amount.Int64()` in the custody adapter, which truncates silently.

```go
// Amount is a non-negative quantity of one asset in its smallest unit.
type Amount struct {
	minor int64
	asset KnownAsset
}

func NewAmount(minor int64, asset KnownAsset) (Amount, error) {
	if minor < 0 {
		return Amount{}, errx.NewKind(1791871689552, errkinds.ErrKindInvalidInput, "amount must be non-negative")
	}

	if err := asset.Validate(); err != nil {
		return Amount{}, errx.Wrap(1793623712936, err)
	}

	return Amount{minor: minor, asset: asset}, nil
}

func (a Amount) Minor() int64      { return a.minor }
func (a Amount) Asset() KnownAsset { return a.asset }
```

### DOM-3 · Time is an input

**Rule.**
- `domain` and `core` never call `time.Now()`.
- Pure functions take `now time.Time` as a parameter.
- Stateful services hold a `clock.Clock` from `foundation`, whose `Now()` returns UTC.
- `*time.Time` means "absent". Never use the zero time for that.

**Why.**
- When time is an input, tests are deterministic without sleeps.
- Without this rule the calls spread: one codebase had 73 `time.Now()` calls in `core` and `domain`, against single digits in two others.
- The clock normalises to UTC, so no caller has to.

**Do.** `PrepareArgs.Now` passes time into a pure use-case.

### DOM-4 · Domain types cross every boundary; `domain` imports no driver

**Rule.**
- **One type per concept, everywhere.** The domain type is the type used in HTTP schemas, use-case args and results, repository parameters and scan destinations, job args, events and caches. There is no per-layer copy of the same shape, and no mapping function between two identical shapes.
- **Tags are allowed.** A domain type may carry `json`, `validate`, `lint`, `spec`, `description` and `example` tags. A tag is metadata and imports nothing.
- **Methods for a driver are allowed** when their signatures use only standard-library or built-in types:
  - `MarshalText`/`UnmarshalText`;
  - `sql.Scanner`/`driver.Valuer`;
  - Mongo v2's `MarshalBSONValue() (byte, []byte, error)`.
- **`domain` imports no driver**: no pgx, pgtype, gocql, mongo-driver or go-redis. It never holds a driver type as a field. Where a driver's interface would need its own types in the signature (gocql's `MarshalCQL`), the repository converts at the call instead (DOM-1).
- **A database schema type is not a domain type.** It describes how a record is stored. It's private to the repository, its fields may use domain types, and repository methods still take and return domain types (DATA-2). Domain types carry no database tags, whatever the database.
- **Any other separate struct exists only when the shape really differs**, such as a public HTTP response shaped differently from the entity. Mapping then copies fields of the same types.
- Optional fields are pointers.

**Why.**
- Per-layer copies of the same shape need a mapping function for every pair, and each one is a place for a field to be forgotten.
- Every backend business concept must use its authoritative `internal/domain` type across HTTP schemas/handlers, models, services, repository interfaces and implementations, database arguments and scan destinations, workers, queues, events, caches, fixtures, and tests. Pass domain values directly through driver-required `any` arguments and scan into domain destinations. A private document type, as with Mongo, is the one exception (DATA-2).
- Keeping driver imports out of `domain` means a core test never needs a database driver to build a value.

**Enforced by** depguard: `internal/domain` may not import any database or cache driver.

### DOM-5 · Invariants live in constructors and `Validate`

**Rule.**
- Value objects (`Amount`, `Email`, ID formats) are created only through `New…`/`Parse…`, which return an error.
- Entities keep exported fields and get a `Validate() error` method rather than a free `ValidateXInvariants(x)` function.
- Validation is split by layer:

| Layer | Validates |
|---|---|
| Transport schema (gofi tags) | Shape and syntax |
| `domain` | Single-entity invariants |
| `core` | Cross-entity policy |

```go
type Transfer struct {
	ID          TransferID
	TenantID    TenantID
	Amount      Amount
	Status      TransferStatus
	CancelledAt *time.Time // nil = not cancelled
	CreatedAt   time.Time  // UTC
	UpdatedAt   time.Time  // UTC
}

func (t Transfer) Validate() error { /* single-entity invariants */ }
```

Pass and return entities by value. Use a pointer receiver only on methods that mutate. Across three codebases, 629 returns were by value against 13 by pointer.

### DOM-6 · Enums are enumx, declared one way

**Rule.**
- Every closed set is a string-kinded enumx type in `domain`.
- Declare it as `enumx.New[T, any](nil)`, or with an unexported `tMeta` struct when the variants carry metadata.
- The fallback is always `nil`, so the zero value `""` is invalid.
- Name variables `<Type><Variant>`.
- Wire values are UPPER_SNAKE. On a `greenfield` scope (COL-15) nothing is frozen, so existing values are renamed to match. On an `existing` scope, a rename is a breaking change, and the plan says how callers move.
- Every enum has `Parse<T>(string) (T, error)`, `Validate() error` and `Oneof() string`, built from a shared sorted helper.

**Why.**
- enumx is the norm: across three codebases, 96 files used it against 1 with `iota`. Without one way to declare it, declarations drift:
  - Wire values mix UPPER and lower.
  - Variables put the type first in some packages (`TransferStatusPending`) and last in others (`QueuedDeliveryStatus`).
- enumx's `Values()` iterates a map, so its order is random. Any `Oneof()` that doesn't sort makes OpenAPI output and validation messages nondeterministic.

```go
type TransferStatus string

var TransferStatuses, setTransferStatus, _ = enumx.New[TransferStatus, any](nil)

var (
	TransferStatusInitiated = setTransferStatus("INITIATED", nil)
	TransferStatusPending   = setTransferStatus("PENDING", nil)
	TransferStatusFailed    = setTransferStatus("FAILED", nil)
	TransferStatusCancelled = setTransferStatus("CANCELLED", nil)
)

func ParseTransferStatus(s string) (TransferStatus, error) {
	if v, ok := TransferStatuses.ById(TransferStatus(s)); ok {
		return v, nil
	}

	return "", errx.NewKindf(1792740595775, errkinds.ErrKindInvalidInput, "invalid transfer status %q", s)
}

func (s TransferStatus) Validate() error { _, err := ParseTransferStatus(string(s)); return err }
func (s TransferStatus) Oneof() string  { return enumtag.Oneof(TransferStatuses.Values()) } // foundation/enumtag (LAY-9)
```

### DOM-7 · State machines

**Rule.**
- One enum per state machine.
- One unexported transition table in `domain`, built with a generic `foundation/statemachine.Table[S]` that provides `Can(from, to)` and `Sources(to)`.
- Entities change state only through `(e Entity) TransitionTo(next, at) (Entity, error)`.
- Repositories persist with a compare-and-set on `table.Sources(next)`. They never hardcode state literals in SQL.
- A test ranges over `X.Values()` and asserts that every state is in the table or is explicitly terminal. This stands in for the `exhaustive` linter, which can't see enumx variables.

**Do.** The domain owns the table and the store enforces it:

```go
// domain
func TransferTransitionSources(to TransferStatus) []TransferStatus { /* ... */ slices.Sort(sources); return sources }
// repository
	params.ConfirmationSource, params.ExpectedStatus, domain.TransferTransitionSources(params.Status),
// SQL:	... AND status = ANY($13)
```

**Don't.** One 15-state `LifecycleState` enum merges several machines (`accepting`, `owned`, `pending`, `complete`, `quarantined`, …), and transitions are ad-hoc `if row.State != models.PendingState` checks.

**Don't.** The transition table is an exported, mutable global:

```go
var ValidTransitions = map[domain.KeyStatus][]domain.KeyStatus{
```

**Canonical:**

```go
var transferMachine = statemachine.New(map[TransferStatus][]TransferStatus{
	TransferStatusInitiated: {TransferStatusPending, TransferStatusCancelled},
	TransferStatusPending:   {TransferStatusFailed},
})

func (t Transfer) TransitionTo(next TransferStatus, at time.Time) (Transfer, error) {
	if !transferMachine.Can(t.Status, next) {
		return Transfer{}, errx.NewKindf(1793215884992, errkinds.ErrKindInvalidTransition,
			"transfer %s: %s -> %s", t.ID, t.Status, next)
	}

	t.Status, t.UpdatedAt = next, at

	return t, nil
}
```

## Abstractions

### ABS-1 · Interfaces belong to the consumer

**Rule.**
- **Where.** The package that calls the methods declares the interface. It declares **one** interface per dependency, listing every method that package calls on it: one `Store` for the transfer repository, not one interface per function. Aim for 1 to 5 methods; 7 is the hard limit, and past it the dependency usually has two roles.
- **Types.** Signatures use only `domain` and stdlib types, or `ports` types for a shared interface. Argument and result structs that a store method needs live in `domain`, beside the entity, such as `domain.CancelInitiatedTransferArgs`. The consumer and the implementation then share them, and nothing is declared twice. Never use types from the implementer's package.
- **Shared.** When two or more packages need the same set of methods, declare it once in `ports/` instead of twice. `foundation/` declares the few interfaces every layer uses, such as `clock.Clock` and `ids.Generator` (DOM-1, DOM-3).
- **One exception: gofi's `Deps`.** HTTP handlers get their dependencies from `deps.MustGet(c)`, and `Deps` is an interface with one accessor for each dependency, returning an interface where the dependency has a real and a fake implementation (HTTP-1, gofi DEP-1 and DEP-2). It grows with the service, so it has no method limit. It doesn't make handlers depend on more than they use, because each handler calls only the accessors it needs.
- **No stranded interfaces.** Every interface has at least one consumer outside its own declaration and at least one implementation in the module, test fakes included.

**Why.**
- A consumer-local interface typed with the repository's own argument structs (`auditrecords.InsertArgs`) still makes the consumer import the implementation, so the inversion is defeated.
- A 26-method `WalletRepository` makes tests embed a nil interface so they can stub one method:

```go
// parkTrackingWalletStore is a minimal WalletStore fake that only implements
// what handleProvisionError's park path touches. Every other method panics if
// called, so an unexpected call site is a loud test failure.
type parkTrackingWalletStore struct {
	domain.WalletRepository
```

If you need to embed an interface in a fake, the interface is too big.

**Bloat and stranding.** Small consumer-owned interfaces can multiply if every function declares its own subset, and an interface can outlive its last user. The first two bullets prevent the first problem: one interface per consuming package, with shared types in `domain`. The last bullet catches the second. Stranded interfaces come from the opposite habit, declaring the interface beside its implementation: six of eleven repository `Store` interfaces declared that way had no consumer (see the **Don't** below).

**Enforced by:**
- `interfacebloat` (max 7), except in `internal/http/deps/`.
- `iface`'s `unused` check. It reports an interface that nothing in its own package uses, which is the right test for a consumer, because the consumer declares the interface where it uses it. `ports/` and `foundation/` are excluded, because their interfaces are used only by other packages.
- An arch test, written with `go/types`, that lists every interface in `internal/` and fails if it:
  - has no implementation in the module;
  - is never used as a parameter, field or variable type outside its own declaration;
  - duplicates another interface's method set in a sibling package.

**Do.** One interface for the dependency, listing the methods this package calls:

```go
// internal/core/transfer/store.go
type Store interface {
	Get(ctx context.Context, tenant domain.TenantID, id domain.TransferID) (domain.Transfer, error)
	CancelInitiated(ctx context.Context, args domain.CancelInitiatedTransferArgs) (domain.Transfer, error)
}
```

**Don't.** An interface declared beside its only implementation. Of 11 repository `Store` interfaces declared this way, six had no consumer at all.

### ABS-2 · Implementations assert and return concrete types

**Rule.**
- Constructors return `*T`. That includes the constructor of gofi's `Deps` implementation, which is a struct (gofi DEP-2).
- The implementing type declares `var _ consumer.Iface = (*T)(nil)` next to its definition.
- Two kinds of function may return an interface:
  - the accessors on gofi's `Deps`, and `deps.MustGet`, as gofi DEP-1 and DEP-2 require (ABS-1);
  - functions that return gofi's own interfaces, such as a router setup function returning the `gofi.Router` that `gofi.NewRouter` gave it.
- Export an interface only when an implementation lives in another package. Test-only seams stay unexported.

```go
// internal/core/transfer/store.go
type Store interface {
	Get(ctx context.Context, tenant domain.TenantID, id domain.TransferID) (domain.Transfer, error)
	UpdateStatus(ctx context.Context, args domain.UpdateStatusArgs) (domain.Transfer, error)
}

// internal/repository/transfers/repo.go
var _ transfer.Store = (*Repo)(nil)

type Repo struct{ db *pgxpool.Pool }

func New(db *pgxpool.Pool) *Repo { return &Repo{db: db} }
```

### ABS-3 · Name by role

**Rule.**

| Kind of interface | Naming | Examples |
|---|---|---|
| Single method | `-er` | `Publisher`, `KeyWrapper` |
| Persistence, in the consumer | `Store` | `transfer.Store` |
| Persistence implementation | `Repo` | `transfers.Repo` |
| Vendor role | Domain noun | `Custodian`, `IdentityVerifier` |

- Never use `I*`, `*Iface`, `*Interface`, `*Impl`, `*Adapter`, `*Manager` or `*Helper`.
- Strays to watch for include `ActivateWorkerIface`, a vendor's name in an interface such as `AcmeOIDCer`, and `*Adapter` types (twelve in one codebase).

### ABS-4 · Pure rules are functions; orchestration is a `Service`

**Rule.**
- Business rules that need no I/O are free functions in `core/<capability>`, or methods on domain types. They take their inputs, including `now`, explicitly.
- Anything that coordinates I/O lives in exactly one `Service` per capability package.

**Do:**

```go
func Prepare(args PrepareArgs) (PrepareResult, error) {
	input, err := ParseProducerRecord(args.RawInput, args.MaxDepth)
	if err != nil {
		return PrepareResult{}, errx.Wrap(1793623713079, err)
	}
	// ...
	if err := Validate(input, args.ValidateArgs); err != nil {
		return PrepareResult{}, errx.Wrap(1793623713217, err)
	}
```

### ABS-5 · Service construction

**Rule.**
- `func New(d Deps) (*Service, error)`. `Deps` lists this package's own interfaces plus `Clock`, `IDs` and its own `Config`.
- `New` validates required dependencies and returns an error. An optional dependency is a named field documented as optional.
- Never silently substitute a `Noop`.
- No exported mutable fields, no `With*` mutators, no variadic optionals.
- Split a service at about 12 exported methods or about 8 dependencies.
- No repository locators and no aggregate "Services" roots. `wire.go` builds each service directly.

**Don't.** The constructor is bypassed so its signature doesn't change, and a required KMS dependency is labelled "optional":

```go
	// ... Set it directly on the returned *Pipeline (e.g.
	// pipeline.Metrics = recorder) rather than through NewPipeline, to
	// avoid changing NewPipeline's signature for every existing caller.
	Metrics metrics.Recorder
// main.go
	pipeline := processor.NewPipeline(repos, eventRegistry)
	pipeline.Metrics = recorder
	pipeline.KeyWrapper = keyWrapper
```

**Don't.** A 21-field god struct takes four positional arguments and a variadic optional, then nine `With*` calls:

```go
pipeline := delivery.NewDeliveryPipeline(executor, persister, queue, env.WorkerGroup, transformer).
	WithRetryScheduler(retryScheduler).
	WithLifecycle(&lifecycle.Store{Repo: repo, Keys: keyManager}).
	// ... 7 more With* calls
```

**Don't.** `if q == nil { q = queueadapter.Noop{} }`. A missing dependency silently becomes a no-op, so work is dropped without any error.

**Canonical:**

```go
package transfer // internal/core/transfer

type Deps struct {
	Store     Store
	Custodian Custodian
	Clock     clock.Clock
	IDs       ids.Generator
}

type Service struct {
	store     Store
	custodian Custodian
	clock     clock.Clock
	ids       ids.Generator
}

func New(d Deps) (*Service, error) {
	if d.Store == nil || d.Custodian == nil || d.Clock == nil || d.IDs == nil {
		return nil, errx.New(1793005224150, "transfer.New: missing required dependency")
	}
	return &Service{store: d.Store, custodian: d.Custodian, clock: d.Clock, ids: d.IDs}, nil

```

### ABS-6 · One use case, one method, one file

**Rule.**
- Each use case is one exported method in its own file (`cancel.go`):

  ```go
  func (s *Service) Cancel(ctx context.Context, args CancelArgs) (CancelResult, error)
  ```

- `Args` and `Result` types live in the `core` package, not in `domain`.
- Use the `<Op>Args`/`<Op>Result` names, rather than `Params`/`Arg`.

**Why.**
- Named inputs survive new fields without breaking callers.
- File-per-use-case makes the capability's surface readable from `ls`.

### ABS-7 · Adapters wrap one SDK, once

**Rule.**
- **One package per external system**, such as `adapters/redis`, `adapters/kafka` or `adapters/awskms`. It's the only package in `internal/` that imports that system's SDK. A `pkg/` engine it builds on, such as a stream queue, may import the SDK too (JOB-4).
  - Each role the service uses the system for (cache, lock, rate limiter, queue, producer, consumer) is a file in that package, not a package of its own.
  - Connection settings (address, TLS, credentials, pool size) are applied in one function. Where one client serves every role, as with Redis, there is one client, and every role type is built from it: `redis.NewLock(client, ttl)`. Where the SDK needs a client per role, such as a Kafka client per consumer group, that same function builds each one.
  - A second package for the same system is right only for a second implementation of the same port that shares nothing with the first, such as a fake KMS for local development. A role, or the package's size, is not a reason.
- It takes its own `Config` struct (never the app config) and exposes `New(cfg) (*T, error)`, with no network I/O in `New`. `New` takes a `ctx` first only when building the client needs one, as loading AWS config does.
- No SDK type appears in any exported signature or field.
- Every SDK error is translated to an errx kind, with the cause wrapped. See [04-errors.md](04-errors.md).
- Don't add intermediate "client interface" layers. Test adapters against the real dependency.
- Fakes are selected in `cmd`, never by a "mode" flag inside the production adapter.
- Name the type for what it is (`s3store.Store`, `awskms.Wrapper`, `redis.Lock`).

**Why one package per system.** The roles share a client, its settings, the key names and often an encryption codec. Split by role, each of those needs its own way across package boundaries. In one codebase, six Redis packages split by role, over one client, brought:
- a seventh package, `redisclient`, that only handed the client around;
- a process-wide map, keyed by the client, to share an encryption codec, which eight places (six process startups and two test harnesses) each had to remember to fill;
- exported key builders, so the queue package could delete the cache package's keys when a project was removed;
- adapters importing other adapters, which the layer table doesn't allow (LAY-7).

In another codebase, two Kafka packages wrote the broker and TLS setup four times.

**Do.** This is the template, using AWS KMS as the example:

```go
// internal/adapters/awskms/wrapper.go
var _ ports.KeyWrapper = (*Wrapper)(nil)

type Wrapper struct {
	client *kms.Client
	kekARN string
}

// New constructs a Wrapper. It performs no network call.
func New(ctx context.Context, cfg Config) (*Wrapper, error) {
// ...
func (w *Wrapper) GenerateDataKey(ctx context.Context, args ports.GenerateDataKeyArgs) (ports.GenerateDataKeyResult, error) {
	out, err := w.client.GenerateDataKey(ctx, &kms.GenerateDataKeyInput{ /* ... */ })
	if err != nil {
		return ports.GenerateDataKeyResult{}, errx.WrapKind(1787900200002, errkinds.ErrKindUnavailable, err)
	}
```

**Don't.** An HTTP handler builds a KMS client and wires a coordinator on every request:

```go
client, err := kms.BuildKMSClient(deps.Env())
// ...
cleanup := &projectcleanup.Coordinator{Repo: deps.Repo(), Objects: objects, Bucket: deps.Env().ArchivalS3Bucket,
	KeyARN: deps.Env().KMSKeyARN, Provider: kms.NewKMSProvider(client)}
```

**Don't.** Three forwarding layers for one SDK: `RealKMSClient`, then `KMSProvider`, then `EnvelopeKeyManager`. The mock client ships in the production package and is selected by a `KMSMode` string.

### ABS-8 · Generics

**Rule.**
- Use generics for code whose body doesn't depend on `T`: codecs, queues, response envelopes, set operations, `statemachine.Table[S]`.
- Never type-switch on a type parameter. Pass the behaviour that varies in as a value.
- Replace a family of copy-pasted per-type accessors with one generic function.

**Don't:**

```go

	var value T
	kind := models.BusinessWork
	switch any(value).(type) {
	case models.DeliveryReceiptJob:
		kind = models.ReceiptWork
```

**Don't.** Five identical `Get<Role>` methods, differing only in the type they assert. One generic function replaces them:

```go

	p, ok := r.providers[name]
```

### ABS-9 · Options, embedding, registries

**Rule.**
- **Options:** services and adapters take a `Config` or `Deps` struct. Functional options are for libraries and test harnesses only.
- **Embedding:** embed interfaces to compose interfaces. Don't embed concrete types such as `sync.Mutex` or a repository; use a named field.
- **Registries:** built in `cmd`, immutable afterwards, and keyed by an enumx type, never a raw `string`.

## Smells and what to do instead

| Smell | Example | Instead |
|---|---|---|
| God repository or service locator | `ScyllaRepository` (186 methods); `repository.Repository` (25 accessors), whose callers get every store | A narrow consumer interface per use (ABS-1) |
| A `Deps` accessor that hands out infrastructure | `http/deps.Deps` with `MongoClient()`, which gives every handler the whole database | Accessors return services and stores, never a client, driver or connection (ABS-1, LAY-3) |
| Interface beside its only implementation, with no consumer | 6 of 11 repository `Store`s | Delete it; let the consumer declare one (ABS-1) |
| Pure forwarder | `domain.OIDCClient`; `KMSProvider` | Delete it; call the wrapped type |
| Speculative code | A `chainregistry` package nothing imports, doc-only `evm`/`solana`/`bitcoin` packages, vendor stubs that return "not implemented", an empty `tenancy` service package | Ship an adapter together with the feature that uses it |
| Mutation after construction | `Pipeline` fields set directly; `With*` chains | `New(Deps)` (ABS-5) |
| Silent default | `if q == nil { q = Noop{} }` (8 sites) | Return an error from `New` |
| Rule inside a handler | Expiry checks in an API-key handler | Move it to `core` (LAY-6) |

**Don't.** A forwarder, and one that sits in `domain`:

```go
type OIDCClient struct{ client coreauth.OIDCer }

func (c *OIDCClient) IsConfigured() bool { return c.client.IsConfigured() }
func (c *OIDCClient) AuthorizeURL(s, p string) string { return c.client.AuthorizeURL(s, p) }
```

**Enforced by.**
- `deadcode` (`golang.org/x/tools/cmd/deadcode`) in `task check`. This catches unwired packages and code reachable only from tests.
- `interfacebloat` (max 7), except in `internal/http/deps/` (ABS-1).
- `iface` (`identical`, `unused`, `opaque`). `unused` is off in `ports/` and `foundation/` (ABS-1).
- `ireturn`, which allows gofi's own interfaces, and is off in `internal/http/deps/`.
- `embeddedstructfieldcheck` (`forbid-mutex`).
- `reassign`.
- forbidigo for `time.Now` in `domain`/`core`.
- The shared architecture test: no database tags in `domain`, assertions present, no `With*` mutators, banned names.
